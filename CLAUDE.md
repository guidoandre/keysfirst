Server code uses SERVER_RPC_URL (env RPC_URL, falls back to NEXT_PUBLIC_RPC_URL).
- Card payments left half-way (tab closed, other device) are found again by /api/checkout/pending (Stripe search on the deal + account metadata) and finished by fulfil; the browser remembers a pending session per deal and account (pendingKey). Checkout sessions expire after 31 minutes. Card fee (matches the pitch deck): 3.5% EEA card, 4.5% other cards, 2% bank (off), min €12; the tenant enters the card in Stripe's Payment Element on the deal page, /api/checkout/quote shows the exact price for the card's issuing country, /api/checkout/pay charges exactly that (no hold). Needs NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY (pk_test_). Fee copy comes from web/src/content/fees.ts. Fulfil no longer tops up SOL: the deal page calls /api/gas right before locking.
- Card mints are once-only on-chain: fulfil creates a marker account derived from the payment intent in the same transaction (mintOnceIx in web/src/lib/server/faucet.ts). Since 3 Oct the marker seed is an HMAC keyed by the faucet secret (lib/server/mint-proof.ts) so nobody can occupy the address first, and "already minted" counts only when isFaucetMint verifies the faucet's own mint (the old public marker is still checked for older payments). A payment found via /pending or a link asks "Lock the deposit?"; only this browser's own payment locks straight away. /api/gas is rate-limited in memory (web/src/lib/server/limits.ts) and stops above a 0.5 SOL faucet reserve.
